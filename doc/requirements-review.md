## 1. 一句话产品定义

在 Chrome / Edge / Firefox 上，用户浏览 GitHub 时可**一键走 Gitee 官方导入**把仓库放到自己的 Gitee，并对已导入仓库做**同步更新（API 或唤起网页 Sync）**；插件只做编排，**不自建 git 同步服务**。

---

## 2. 问题拆解

| 问题 | 痛点 | 插件怎么解 |
|---|---|---|
| 新增备份 | 要自己找 Gitee「从 GitHub 导入」入口 | GitHub 页一键跳转/预填导入 |
| 持续同步 | 要记起到 Gitee 点「同步更新」 | 映射列表 + 手动同步 + 有更新提醒（能自动则自动） |
| 使用成本 | 自建服务/Python/SSH 太重 | **只装插件 + 用 Gitee 账号** |
| 完整历史 | Contents API 无历史 | **交给 Gitee 官方导入/同步** |

---

## 3. 范围

### 3.1 In Scope

- 场景 B：公开仓 → 启动 Gitee 官方导入 + 登记映射
- 场景 A：映射列表、手动同步、轮询「有更新」、尽量触发官方同步
- Gitee Token（查仓/尽量调同步 API）
- Chrome / Edge / Firefox

### 3.2 Out of Scope

- 自建 sync-service 作为必选依赖
- 扩展内 git / Contents 全量快照当主方案
- 反向同步、组织批量、LFS SLA、商店上架（P1/后置）

### 3.3 相对 v0.2 的变化

| 项 | v0.2（旧） | v1.0（现） |
|---|---|---|
| D-01 | 插件 + 薄同步服务 | **插件 + Gitee 官方导入/同步** |
| 首次同步 | 服务端 `git mirror` | Gitee「从 GitHub 导入」 |
| 再次同步 | 服务端 mirror | 「同步更新」或 Pull 镜像触发 |
| sync-service | MVP 核心 | **已删除（v1.1）** |

---

## 4. 用户故事（P0）

1. 在 GitHub 仓页点「导入到 Gitee」，进入官方导入并完成搬家。
2. 导入后在插件登记映射，以后能看到状态与链接。
3. 对已映射仓点「立即同步」，完成更新或被带到 Gitee「同步更新」。
4. GitHub 有新提交时，列表显示「有更新」（能自动跟就跟）。
5. 三端都能用；无需部署任何自建同步服务。

---

## 5. 业务规则

| ID | 规则 |
|---|---|
| R-01 | 一个 GitHub 仓同时仅一个活跃 Gitee 映射 |
| R-02 | 移除映射不删 Gitee 仓 |
| R-03 | 同步更新可能强制覆盖，必须提示 |
| R-04 | 他人仓不做对方 webhook 假设 |
| R-05 | 官方能力不可静默调用时，允许「打开网页让用户点一下」且不算失败隐藏 |
| R-06 | Token 本地存储、日志脱敏 |
| R-07 | 同名冲突由用户在导入页或插件中显式处理 |
| R-08 | MVP 成功标准允许「半自动」（跳转确认），不强制 100% 无感 API |
